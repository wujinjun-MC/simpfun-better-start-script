# 与 OPanel 的对比

本文档对比 `simpfun-better-start-script` 与 OPanel（https://opanel.cn/en/）在定位、功能、适用场景和优缺点方面的差异。

大部分由AI生成，以实际体验为准。

## 项目定位

- `simpfun-better-start-script` 是一个针对简幻欢 Minecraft 服务器的启动脚本与运行环境增强项目。
  - 重点是：启动/重启管理、终端控制、性能优化、存档保护、低带宽远程调试和预置工具。
  - 使用场景：在受限环境（Docker容器，`/home/container`之外全部只读，缺少必要工具）上安全稳定运行 Minecraft 服务器并提供个性化体验。

- OPanel 是一个 Minecraft 服务器管理面板插件 / mod。
  - 重点是：Web 控制面板、服务器实时监控、游戏内编辑、地图展示、API 扩展、支持多种 Minecraft 服务端平台。
  - 典型使用场景：希望通过图形界面管理服务器、提供玩家可视化运营面板、集成开放 API 和插件生态。

## 功能对比

### `simpfun-better-start-script` 主要功能

- 本地与远程终端管理
  - 通过 `tmux` 让服务器在断开连接后继续运行
  - 支持 SSH、Tmate、Telnet（TODO）远程接入
- 启动与自动重启
  - `start-part-mcserver.sh` 负责启动 Minecraft 服务器
  - 自动重启、防止异常退出导致存档损坏
- 性能与资源优化
  - 快速配置 JVM 参数
  - 内置 `btop`、`htop`、`ncdu` 等性能/磁盘工具
- 存档保护
  - 0:00~1:00自动“休眠”服务器并保存存档，避免积分不足强制关机导致存档损坏
- 预置二进制工具
  - 提供常用工具，无需手动编译或安装依赖
- 目标是轻量、可直接部署的启动脚本，适合资源受限环境 (每天有上传流量限额)

### OPanel 主要功能

- Web 管理面板
  - 可通过浏览器查看服务器状态、日志、控制台
- 多平台支持
  - 支持 Paper、Folia、Fabric、Forge、NeoForge 等主流平台
- 游戏内工具
  - 可视化库存编辑器
  - 实时内置地图展示（BuiltinMap）
  - 服务器终端、命令补全、彩色日志
- 扩展与 API
  - 支持 MCP 扩展、开放 API、第三方 AI agent 集成
  - 提供插件开发与扩展能力
- 更偏向于服务器运营、玩家体验和可视化功能

## 优势对比

### `simpfun-better-start-script` 的优势

- 轻量：不依赖 Web 面板、浏览器或额外插件，仅靠 Shell 脚本即可运行
- 低带宽友好：面向 SSH/Tmate 等终端管理，适合网络不稳定或限速场景
- 原生支持：专为简幻欢服务端及其容器式部署提供直接启动优化
- 部署简单：只需复制脚本、配置权限和配置区即可使用
- 资源保护：内置“积分不足时自动休眠”策略，适合免费或低资源服
- 自带工具：捆绑 `btop`、`htop`、`ncdu` 等常见维护工具，免去额外安装依赖

### OPanel 的优势

- 图形界面：Web 控制面板让服务器管理更加直观、适合运营和玩家使用
- 功能丰富：实时地图、库存编辑、API 扩展、MCP 集成等高级功能
- 多平台插件：对多种 Minecraft 服务端类型提供统一管理支持
- 更强的运营属性：玩家统计、日活、后台任务、可视化管理功能更完善

## 不足与限制对比

### `simpfun-better-start-script` 的不足

- 没有 Web UI：无法直接提供浏览器面板或图形化运维界面
- 不是插件/Mod：无法像 OPanel 那样直接访问游戏内数据、修改玩家状态或展示地图
- 平台依赖较弱：仅面向 Minecraft 服务端启动与运行，不支持丰富的插件平台功能
- 需要命令行技能：用户需要一定 Shell/终端操作能力

### OPanel 的不足

- 资源开销更大：Web 面板、插件系统和后台服务需要更多内存/CPU
- 部署复杂度更高：需要安装插件/Mod、配置 Web 面板和对应服务器平台
- 依赖服务端兼容性：某些 Minecraft 平台或版本可能不完全兼容或需要额外适配
- 安全面更广：如果开放 Web 控制面板，需要更多安全防护，例如认证、端口管理、TLS
- 完全依赖服务器运行：插件的"权限"小于终端，OPanel插件不加载，相关功能无法使用，不适用于服务器启动失败时手动调试等"edge cases"

## 适用场景建议

- 适合 `simpfun-better-start-script` 的场景：
  - 纯终端管理、无需 Web 面板
  - 资源受限、希望最小化额外服务与依赖
  - 快速部署在简幻欢环境，针对特定问题进行优化，例如重启保护和低带宽远程执行
  - 只关注服务器启动、运行和基础监控，不需要复杂玩家运营功能

- 适合 OPanel 的场景：
  - 需要 Web 控制面板、图形化运维和更多可视化功能
  - 希望在 Paper/Fabric/Forge 等平台上直接集成服务器插件生态
  - 希望提供玩家可见面板、实时地图、库存管理等运营工具
  - 需要对外提供 API、扩展能力和第三方集成

## 总结

`simpfun-better-start-script` 与 OPanel 并不是完全同类产品。

- 如果目标是“简洁、稳定、低成本地管理 Minecraft 服务器启动与运行”，本项目更合适。
- 如果目标是“构建可视化、可扩展的服务器运营面板”，OPanel 更适合。

这两个项目可以视为互补：

- `simpfun-better-start-script` 负责服务器启动、终端管理和资源保护
- OPanel 负责 Web 面板、游戏内可视化和运营管理
